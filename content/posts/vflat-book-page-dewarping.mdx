문서 스캐너 앱은 보통 종이의 네 모서리를 찾아 사다리꼴로 찍힌 페이지를 직사각형으로 바꾼다. 펼친 책을 이렇게 보정하면 바깥 테두리는 반듯해져도 책등 쪽 글줄은 휜 채로 남는다.

책 스캔 앱 vFlat을 만든 VoyagerX는 이 문제를 푸는 방식을 몇 군데에 공개했다. 2019년 개발진이 TensorFlow 블로그에 쓴 기고, 발명자 네 명 중 세 명이 그 기고자인 미국 특허, 그리고 vFlat 공식 블로그다. 특허 본문에는 vFlat이라는 이름이 나오지 않고, 특허는 가능한 구현 하나를 설명하는 문서라서 지금의 앱이 그대로 동작한다고 볼 수도 없다. 자료에 없는 부분을 추정한 곳은 그 자리에서 밝혔다.

## 네 모서리 보정은 페이지를 평면으로 본다

네 모서리로 하는 보정은 호모그래피라는 3×3 행렬 하나로 사진 속 페이지와 직사각형을 대응시킨다. 호모그래피는 [두 평면 사이의 변환](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html#tutorial_homography_What_is_the_homography_matrix)이라서 페이지 전체가 한 평면 위에 있을 때 맞는다.

펼친 책은 책등 쪽으로 말려 올라가 있어서 페이지의 자리마다 카메라와의 거리와 기울기가 다르다. 행렬 하나로는 이 자리들을 한꺼번에 맞출 수 없다. vFlat 블로그도 [기울기만 맞추면 휘어진 글줄이 남는다](https://vflat.com/ko/blog/curves-flattened)고 설명한다.

## 특허는 휜 페이지를 숫자 몇 개로 나타낸다

[미국 특허 10,991,081](https://patents.google.com/patent/US10991081B1/en)은 VoyagerX가 2020년 12월에 출원해 2021년 4월에 등록한 "Book scanning using machine-trained model"이다. 특허가 설명하는 구현은 페이지가 평평할 때 직사각형이고, 펼치면 원통면의 일부처럼 말린다고 가정한다. 원통면이므로 책등에 수직인 면으로 자른 단면은 어디서 잘라도 같은 곡선이 되고, 곡선 하나로 페이지 전체의 휨을 나타낼 수 있다.

이 곡선은 제어점 네 개로 정하는 3차 베지어 곡선이다.

```text
B(s) = (1-s)^3·P0 + 3(1-s)^2·s·P1 + 3(1-s)·s^2·P2 + s^3·P3,  0 ≤ s ≤ 1
```

좌표는 페이지 폭을 1로 둔 비율로 쓴다. 양 끝점 P0과 P3은 페이지의 왼쪽·오른쪽 아래 모서리로 고정하고, 가운데 두 제어점의 가로 위치를 폭의 1/4과 3/4로 고정하면 남는 값은 두 제어점의 높이 Z1, Z2뿐이다. 특허의 그림에 나온 곡선은 이 두 값이 0.16과 0.32다.

사진 속 페이지 모양은 카메라에도 달려 있다. 특허는 카메라를 핀홀 카메라로 모델링하고, 곡률과 함께 아래 값들로 촬영 상황을 나타낸다.

| 나타내는 것 | 파라미터 |
| --- | --- |
| 페이지 곡률 | 베지어 곡선 제어점의 높이 Z1, Z2 |
| 카메라 방향 | roll, yaw, pitch 세 각도 |
| 카메라 위치 | 가로·세로 이동량, 초점거리 |
| 페이지 크기 | 평평하게 편 이미지에서 페이지가 차지하는 폭·높이 비율 |

이상적인 핀홀 카메라에서는 초점거리 값 하나로 카메라가 페이지에서 떨어진 거리까지 나타낼 수 있어서, 특허는 거리 값을 따로 두지 않는 구현을 설명한다.

이 값들을 정하면 사진은 평평한 페이지를 이 곡선대로 만 뒤 그 위치·방향의 카메라로 찍은 결과로 볼 수 있다. 특허 청구항 1은 페이지 펴기를 이 과정을 거꾸로 되돌리는 변환으로 정의한다.

특허는 별도의 3D 스캔 장치가 있다면 곡면을 직접 잴 수도 있다고 적지만, 중심이 되는 구현은 학습된 모델이 사진에서 이 값들을 추정하는 방식이다. vFlat 공식 FAQ도 [사진 한 장에서 입체 곡면을 분석한다](https://vflat.com/ko#faq)고 설명한다.

## 신경망은 작은 사진에서 숫자만 맞힌다

특허에서 학습된 모델의 출력은 펴진 이미지가 아니라 위 표의 파라미터다. 예시로 든 모델은 합성곱 신경망이고, 입력은 3200×2400 사진을 192×144로 줄인 RGB 이미지다. 픽셀 수로는 원본의 1%도 안 된다.

이 크기에서는 사진에서 30×30픽셀이던 글자가 사람이 알아볼 수 없을 만큼 작아진다. 특허는 모델이 파라미터를 내는 데 읽을 수 있는 글자가 필요하지 않다고 쓰고, 입력을 작게 하면 모델의 내부 파라미터 수와 계산량을 줄일 수 있다고 설명한다.

청구항 1은 펴는 대상을 촬영 이미지나 그 가공본으로 적고, 청구항 4는 모델 입력을 촬영 이미지보다 낮은 해상도로 만든다고 적는다. 작은 이미지는 페이지 모양을 정하는 데만 쓰고, 결과 이미지는 촬영한 사진 쪽에서 만든다.

페이지 크기 비율은 배경을 잘라 내는 데 쓴다. 특허의 구현에서는 평평하게 편 페이지가 결과 이미지 한가운데 놓인 직사각형이 되므로, 폭·높이 비율만 알면 페이지 테두리를 따로 찾지 않고 비율대로 잘라 배경을 지울 수 있다.

## 픽셀은 원본 사진에서 가져온다

특허는 펴는 과정을 곡면·카메라 모델로 왜곡을 되돌리는 계산이라고만 쓰고, 픽셀을 옮기는 방법까지는 적지 않았다. 이런 변환은 보통 결과 이미지 쪽에서 거꾸로 계산한다. [OpenCV의 기하 변환](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)도 결과 이미지의 픽셀마다 원본에서 대응하는 좌표를 구하고, 그 좌표가 정수가 아니면 주변 픽셀을 보간해 값을 가져온다.

아래는 이 방식으로 특허의 흐름을 옮겨 본 예시 코드다. 특허나 앱의 코드가 아니고, `model`과 `project_to_photo`는 각각 학습된 모델과 곡면·카메라 모델 계산을 나타낸다.

```python
import cv2
import numpy as np


def flatten(photo, params, out_w, out_h):
    # 결과 이미지의 픽셀마다 페이지 위 좌표 (u, v)를 만든다.
    u, v = np.meshgrid(np.linspace(0, 1, out_w), np.linspace(0, 1, out_h))

    # (u, v)를 말린 페이지 위의 3D 점으로 옮기고 카메라로 투영해
    # 원본 사진 속 위치를 구한다.
    map_x, map_y = project_to_photo(u, v, params)

    return cv2.remap(
        photo,
        map_x.astype(np.float32),
        map_y.astype(np.float32),
        cv2.INTER_LINEAR,
    )


small = cv2.resize(photo, (192, 144), interpolation=cv2.INTER_AREA)
params = model(small)  # 곡률, 카메라 방향·위치, 페이지 크기
page = flatten(photo, params, out_w, out_h)  # 원본 사진에서 픽셀을 가져온다
```

이 구조에서 신경망은 좌표를 정하는 숫자만 내고, 결과 이미지의 색은 원본 사진에서 가져온다. 글자를 새로 그리는 단계가 없다.

vFlat 공식 블로그는 지금 앱의 처리 과정을 [이렇게 설명한다](https://vflat.com/ko/blog/how-vflat-flattens-a-curved-page). 평평한 페이지에 촘촘한 격자를 그렸다고 상상하면, AI가 그 격자가 사진 속 어디에 놓였는지를 한 번에 알아낸다. 그다음 격자 칸마다 사진 조각을 떼어 반듯한 사각형 위에 다시 그린다. 그래도 남은 미세한 물결은 프리미엄 기능인 '더 펴기'로 한 번 더 바로잡을 수 있다.

블로그는 데모 속 책과 격자가 설명을 위해 그린 장면이라고 밝히고 있어서, 실제 계산 방식까지 알 수는 없다. 그래도 페이지 위 좌표가 사진의 어디에 놓이는지 구한 뒤 사진 조각을 옮겨 온다는 설명은 위 예시와 같은 구조로 읽힌다. 이 격자를 특허처럼 곡률·카메라 값에서 계산하는지, 신경망이 직접 내놓는지는 밝히지 않았다.

이어서 책등 그림자와 누렇게 바랜 종이색을 걷어내고, 손가락을 지우고, 페이지 바깥을 잘라 낸다고 적었지만, 이 단계들을 어떻게 처리하는지까지는 설명하지 않는다.

## 정답 파라미터를 만드는 두 가지 방법

모델이 파라미터를 내도록 학습시키려면 학습용 사진마다 정답 파라미터가 있어야 한다. 실제로 말린 페이지를 찍은 사진만으로는 그 값을 알 수 없다. 특허는 정답을 만드는 방법을 두 가지 설명한다.

첫째는 표식을 인쇄하는 방법이다. 책 페이지의 정해진 위치에 원형 점 25개를 5×5로 인쇄하고, 그 페이지들로 책을 묶는다. 펼친 페이지를 카메라 위치나 말린 정도를 바꿔 가며 찍거나, 페이지를 넘기는 영상을 찍어 프레임을 사진으로 쓴다.

그다음 파라미터 값을 하나 정하고, 그 값대로라면 각 점이 사진의 어디에 찍혀야 하는지 계산한다. 실제 사진 속 점 위치와 차이를 손실로 계산하고, 손실이 기준보다 크면 값을 고쳐 다시 비교한다. 특허는 값을 고치는 방법의 예로 손실의 편미분과 뉴턴-랩슨법을 든다. 손실이 기준 아래로 내려가면 그 값이 이 사진의 정답이 된다. 모델에 넣을 입력 사진에서는 점을 종이색으로 칠해 지우는데, 점과 겹친 글자도 함께 지워진다.

둘째는 시뮬레이션이다. 정답 파라미터를 먼저 정하고, 평평한 페이지 이미지를 같은 핀홀 카메라·베지어 곡선 모델로 왜곡해 말린 페이지 사진을 만든다. 반복 계산 없이 학습 데이터를 많이 만들 수 있고, 실제 촬영으로는 담기 어려운 카메라 위치와 방향도 다룰 수 있다.

특허는 입력과 정답 쌍 10만 개를 예로 들면서 그보다 적거나 많을 수 있다고 덧붙였다. 앱의 실제 학습 데이터 규모를 알려 주는 숫자는 아니다.

## 펴는 일은 휴대폰에서, 글자 인식은 서버에서

2019년 TensorFlow 블로그 기고는 당시 Android 앱의 이야기다. 개발진은 휘어진 페이지를 펴는 딥러닝 모델을 [휴대폰에서 실행하기로 했고](https://blog.tensorflow.org/2019/08/how-vflat-used-tflite-gpu-delegate-for-realtime-interference-scan-books.html), 앱의 실시간 미리보기는 초당 20프레임 이상으로 페이지를 펴서 보여 줬다. 사용자는 이 미리보기를 보며 찍기 전에 각도와 구도를 고칠 수 있다.

이를 위해 가중치 수와 복잡한 연산을 줄인 가벼운 모델을 만들고, TensorFlow Lite의 GPU 대리자(delegate)를 썼다. 당시 실험 버전의 GPU 대리자가 지원하지 않던 LeakyReLU는 음수 쪽 기울기를 0.3으로 고정한 PReLU로 바꿨고, 입력 정규화에 쓴 Lambda 층이 경고 없이 CPU로 넘어가는 문제도 겪었다. 기고는 GPU 대리자를 써서 CPU에서 돌릴 때보다 추론 시간을 절반 넘게 줄였다고 적었다. 이 기고는 모델 구조를 밝히지 않아서, 당시 모델이 특허의 파라미터 방식이었는지는 알 수 없다.

지금도 촬영, 테두리 인식, 곡면 보정, 손가락 지우기는 [휴대폰 안에서 처리하고](https://vflat.com/ko/blog/how-on-device-processing-keeps-scans-private) 서버로 보내지 않는다고 공식 블로그는 설명한다. 서버를 거치는 기능은 문자 인식(OCR)과 PC로 보내기이고, OCR에는 Google Cloud Vision을 쓴다. vFlat은 [글자를 인식하기 전에 곡면부터 보정한다](https://vflat.com/ko/blog/what-makes-ocr-accurate-on-a-phone-camera). 휘어진 페이지에서는 같은 글자도 자리에 따라 눌리거나 늘어나 보여서 인식이 어려워지기 때문이다.
