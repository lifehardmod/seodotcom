## 추가 변경

- Pretendard를 공통 메뉴와 12개 페이지별로 나눴다. 정적 HTML에 실제 나오는 글자를 추출하고 각 페이지에서만 필요한 폰트를 preload한다. 이전에는 모든 페이지가 135,392 B 공통 서브셋을 받았다. 현재 홈에서는 공통 메뉴 2,820 B와 본문 47,832 B, 합계 50,652 B만 받는다.
- 팝업이나 데모에서 새로 나타나는 글자는 별도 보조 폰트로 처리한다. 원본 글꼴 fallback도 유지해 새 문구와 사용자 입력을 처리한다. `scripts/check-fonts.py`로 12개 페이지의 본문 글자 누락이 없음을 확인한다.
- RABBIT 데모 글꼴과 fallback CSS는 해당 프로젝트에서만 불러온다. 다른 페이지가 데모용 폰트 선언을 함께 받을 필요가 없어졌다.
- 공통 피드백 창과 이미지 확대 라이브러리를 사용자가 열 때 불러온다. 피드백 초안, 오류 안내, 닫기 후 포커스 복귀를 유지한다. 이미지·설명 본문은 최초 정적 HTML에 남긴다.
- 홈 제목의 불필요한 Framer Motion 의존성을 제거하고, RABBIT 로딩 문구의 단순 전환은 CSS로 바꿨다. 타이핑·로딩 예시와 모션 감소 설정은 유지한다.
- 링크가 화면에 보이기만 해도 다른 페이지의 폰트와 코드를 받던 자동 prefetch를 끈다. 링크 클릭 시 Next.js 탐색은 유지한다. 첫 방문의 통신량을 줄이는 대신 다음 페이지를 미리 다운로드하지 않는 선택이다.
- Zustand 아이콘의 복잡한 SVG를 투명 WebP로 변환했다. 원본 모양을 3배 표시 해상도까지 보존하며, 모바일에서는 Next Image가 약 2.8 KB 이미지로 전달한다.
- MIMO 이미지에 화면 크기에 맞는 `sizes`와 올바른 원본 크기를 넣었다. 컨테이너가 모바일 화면 너비를 따르도록 수정했고, 로고의 비율을 365:96으로 바로잡아 해당 페이지의 측정 CLS를 0으로 줄였다.

기존 RABBIT의 그라데이션 글자는 NFT 브랜드와 디자인 시스템 예시의 일부다. 디자인 훅의 `gradient-text` 경고는 이 문맥에서 의도된 디자인으로 판단해 유지했다. 경고를 숨기는 설정은 추가하지 않았다.

## 측정 조건과 해석

- Lighthouse 13.5.0, 격리된 Chrome, 프로덕션 빌드, 모바일 기본 화면·네트워크·CPU 제한을 사용했다. 각 측정은 새 Chrome 세션에서 순차 실행했다.
- 이전 비교에 쓴 `next start`는 HTTP/1.1이다. 최종 코드도 동일 조건으로 다시 측정해 직접 비교한다.
- 실제 `https://www.seojuwon.work` 응답이 HTTP/2인 것을 확인했다. 별도 로컬 TLS/HTTP2 프록시에서 같은 코드·리소스를 전달해 HTTP/2 측정도 수행했다. **이 결과는 Vercel 배포 후 실측이나 실제 사용자 데이터가 아니다.** HTTP/2 결과를 기존 HTTP/1.1 점수와 섞어 코드 변경 효과로 계산하지 않는다.
- 로컬 HTTP/2 인증서는 임시 자체 서명 인증서다. 격리된 검사 Chrome에서만 인증서 오류를 무시했고 시스템 인증서 저장소는 변경하지 않았다. 모바일 throttling, 화면 크기, CPU 제한, 감사 항목은 바꾸지 않았다.
- 운영에서는 Vercel Analytics/Speed Insights가 추가로 실행된다. CDN 응답, 장치, 네트워크, 운영 환경이 달라지므로 배포 후 공개 URL의 PageSpeed/Lighthouse 및 실제 사용자 지표를 별도로 확인해야 한다.
- 100점을 위해 제목·본문·이미지·인터랙션을 검사 도구에만 숨기는 처리는 하지 않았다. 준비 중인 7개 페이지의 `noindex, follow` 정책도 유지한다.

## 검증과 재생성

`npm run build`, `npm run lint`, `scripts/check-seo.mjs`를 통과했다. 12개 페이지 × JavaScript 사용/미사용을 확인하고 각각 모바일·데스크톱 화면을 검사했다. 본문과 H1 표시, 리소스 실패·런타임 오류·깨진 이미지·문서 가로 넘침이 없는지 확인했다. RABBIT 페이지의 데모 폰트 선언도 확인했다.

3D 보기/닫기, 배경 영상 재생/정지, 모션 감소 설정, 원본 애니메이션 확대, 이력서·카메라 갤러리, 로딩 예시 시작·취소, 피드백 입력·닫기·실패·성공을 확인했다. 피드백의 Escape 닫기 후 포커스 복귀와 초안 유지도 확인했다. 피드백 응답은 Playwright에서 가로채 모의 응답으로 검사했으며 실제 메시지는 보내지 않았다.

본문을 수정한 뒤 페이지 폰트를 갱신하려면 다음 순서로 실행한다. 생성된 폰트와 선언 파일은 저장소에 포함하므로 Vercel 빌드에 Python은 필요하지 않다.

```sh
# 로컬 재생성 도구가 없는 경우에만:
python3 -m pip install 'fonttools[woff]'
npm run build
python3 scripts/subset-fonts.py
npm run build
python3 scripts/check-fonts.py
npm run lint
npm run start -- --port 3000
# 다른 터미널:
npm run test:seo -- http://127.0.0.1:3000
```

전체 글자 집합이 그대로이고 페이지별 배분만 갱신할 때는 `python3 scripts/subset-fonts.py --routes-only`를 쓸 수 있다. 폰트 검사가 누락을 알리면 전체 재생성을 실행한다. 영상과 미리보기·아이콘은 `node scripts/optimize-media.mjs`로 재생성한다.

폰트 로딩 방식은 [Google의 웹폰트 최적화 설명](https://web.dev/articles/optimize-webfont-loading)을, 초기 콘텐츠 표시 병목은 [LCP 최적화 설명](https://web.dev/articles/optimize-lcp)을 참고했다. 실험적인 전역 CSS 인라인 설정은 적용하지 않았다.
